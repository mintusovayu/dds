# ADR-042: Использование `frozen=True` для SearchResult

| Поле | Значение |
|---|---|
| Дата | 2025-01-15 |
| Автор | ivanov |
| Статус | accepted |
| Фаза внедрения | 6 |

## Контекст

`SearchResult` создаётся в `FTS5SearchBackend.search` и передаётся
через слои application → presentation. В текущей реализации это
обычный dataclass без frozen; поле `pages: tuple[PageHit, ...]`
иммутабельно, но сам контейнер — нет. Клиенты могут случайно
вызвать `result.pages = [...]`, сломав ожидания нижележащего кода.

## Альтернативы

### Альтернатива 1: оставить обычный dataclass

**Плюсы.** Не требует изменений в коде.

**Минусы.** Иммутабельность не enforced на уровне типа; mypy не
ловит попытки мутации.

**Итог.** Отклонена: контракт важнее.

### Альтернатива 2: frozen=True без slots

**Плюсы.** Иммутабельность enforced.

**Минусы.** Сохраняется `__dict__`, дополнительная память
на каждый экземпляр.

**Итог.** Отклонена в пользу варианта 3.

### Альтернатива 3: frozen=True, slots=True

**Плюсы.** Иммутабельность + экономия памяти.

**Минусы.** Ограничение на добавление атрибутов в runtime
(не требуется для DDS).

**Итог.** Принята.

## Решение

Применён `@dataclass(frozen=True, slots=True)` к `SearchResult` и
`PageHit`. Поле `pages` — `tuple[PageHit, ...]`, не `list`.

Инвариант: бэкенд конвертирует `list` в `tuple` перед созданием
`SearchResult`.

## Последствия

### Положительные

- Иммутабельность гарантирована типом.

### Отрицательные

- `PageHit` и `SearchResult` нельзя модифицировать на месте;
  для «изменённой копии» — `dataclasses.replace`.

### Нейтральные

- Память на 1 экземпляр сокращается на ~64 байта.

### Известные ограничения

- **Нельзя добавить атрибут в runtime.** Обоснование: DDS не
  использует это; отказ от slots ради редкого сценария
  не оправдан.

## Ссылки

- Реализация: `dds_core/domain/models.py`
- Тесты: `tests/test_search_pages_are_tuple.py`
